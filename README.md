# Armen Articles

Source for [articles.armenderoian.dev](https://articles.armenderoian.dev), a static technical publication for articles, tutorials, and write-ups by Armen Deroian. Articles are Markdown/MDX files in this repository; the site is built with Astro and served as static assets by Cloudflare Workers. There is no server, database, CMS, or login.

> The articles currently in `src/content/articles/` are **demonstration content** that exercise the publishing features. They are labelled as such on the site.

To write an article, read the **[authoring guide](docs/authoring.md)**.

## Features

- **Content:** Markdown and MDX in a type-safe content collection with strict, Zod-validated frontmatter. Invalid metadata fails the build with messages that name the file, the field, and the allowed values.
- **Pages:** home, paginated archive (`/articles`, `/articles/page/2`, …; no JavaScript needed), article pages, categories, tags, series, search, a custom 404, RSS (`/rss.xml`), a sitemap, and `robots.txt`.
- **Articles:** reading time, a table of contents (sidebar on wide screens, collapsible on small ones), series navigation in author-defined order, and deterministic related articles.
- **Rendering:** build-time syntax highlighting with Expressive Code (titles, line highlights, line numbers, diffs, copy buttons, light/dark themes), build-time KaTeX math, theme-aware Mermaid diagrams loaded only on pages that use them, and isolated React islands in MDX.
- **Search:** [Pagefind](https://pagefind.app/) static index of published articles, with a keyboard-accessible search page at `/search`.
- **Theme:** light and dark themes that follow the system preference, with a persistent toggle and no flash on load.
- **Accessibility:** semantic landmarks, a skip link, visible focus, keyboard-scrollable code/tables/equations, reduced-motion support, and automated axe checks against WCAG 2.2 AA in both themes.
- **SEO:** canonical URLs, Open Graph/Twitter metadata, Schema.org `TechArticle` and `BreadcrumbList` JSON-LD, RSS, and a sitemap.
- **Security:** a strict Content-Security-Policy and other security headers generated into `dist/_headers` at build time; no inline scripts apart from Astro's island bootstrap, which is allowed by hash.

## Stack

Astro 7 (static output) · TypeScript (strictest) · MDX · Content Collections + Zod · Tailwind CSS 4 + Typography · Expressive Code (Shiki) · KaTeX · Mermaid · Pagefind · React 19 (islands only) · Vitest · Playwright + axe · ESLint · Prettier · Wrangler.

## Requirements

- Node.js **24** (see `.nvmrc`; 22.18 or newer works). `scripts/generate-headers.ts` runs on Node's built-in TypeScript type stripping.
- npm.

## Getting started

```bash
nvm use            # or install Node 24
npm install
npm run dev        # http://localhost:4321
```

The dev server renders drafts (with a banner). Search does not work under `npm run dev` because the Pagefind index is generated by the production build; use `npm run build && npm run preview` to try it.

## Scripts

| Script                     | What it does                                                                             |
| -------------------------- | ---------------------------------------------------------------------------------------- |
| `npm run dev`              | Astro dev server with drafts.                                                            |
| `npm run build`            | Production build to `dist/`, then the Pagefind index, then `dist/_headers`.              |
| `npm run preview`          | Serve `dist/` with Astro's preview server.                                               |
| `npm run preview:worker`   | Serve `dist/` with `wrangler dev`, matching Cloudflare's routing and headers.            |
| `npm run check`            | `astro check`: TypeScript and content collection validation.                             |
| `npm run lint`             | ESLint.                                                                                  |
| `npm run format`           | Prettier (write). `npm run format:check` verifies only.                                  |
| `npm test`                 | Unit tests (Vitest).                                                                     |
| `npm run test:integration` | Integration tests against `dist/` (run `npm run build` first). Includes link validation. |
| `npm run test:e2e`         | Playwright browser tests against `dist/` (run `npm run build` first).                    |
| `npm run validate`         | check + lint + format check + unit tests.                                                |
| `npm run deploy`           | Build and publish with Wrangler (requires Cloudflare credentials; see below).            |

## Testing

```bash
npm run validate
npm run build
npm run test:integration
npx playwright install chromium   # once
npm run test:e2e
```

- **Unit** (`tests/unit`): slugs and URLs, frontmatter schema errors, draft filtering, sorting, series ordering, related articles, reading time, pagination, taxonomy, structured data, security headers, the Markdown plugins (run through the real pipeline), and client-side helpers.
- **Integration** (`tests/integration`): inspects the production build: every published article is generated and drafts are absent everywhere (pages, RSS, sitemap, search index); canonical/Open Graph/JSON-LD metadata; series order and `rel=prev/next`; RSS entries; every internal link and `#fragment` resolves under Cloudflare's routing rules; the search index contains published article content but not navigation chrome. A fixture under `tests/fixtures/invalid-metadata` proves that bad frontmatter fails the build.
- **Browser** (`tests/e2e`): reader journeys, table of contents, categories, tags, series navigation, search (including keyboard navigation), theme default/toggle/persistence, Mermaid re-theming, math and diagram scoping, the React island, the 404 page, skip link and focus visibility, horizontal overflow at 375px, and axe WCAG 2.2 AA scans of key pages in both themes.

## Configuration

- **Site URL, name, author, page sizes:** `src/data/site.ts` (the URL is also Astro's `site`, used for canonical URLs, RSS, and the sitemap).
- **Categories / series:** `src/data/categories.ts`, `src/data/series.ts`.
- **Markdown pipeline:** `src/lib/markdown/processor.ts`. Expressive Code options live in `astro.config.ts`.
- **Security headers and caching:** `src/lib/security/headers.ts`, written to `dist/_headers` by `scripts/generate-headers.ts` after each build. The CSP allows scripts only from this origin plus the SHA-256 hashes of inline scripts found in the build output (Astro's island bootstrap). Styles allow `'unsafe-inline'` because KaTeX and Mermaid emit inline styles.

After changing remark/rehype plugins, clear Astro's content cache so articles are re-rendered: `rm -rf node_modules/.astro .astro`.

## Deployment

The site deploys to **Cloudflare Workers static assets** (no Worker script). `wrangler.jsonc` serves `dist/`, uses `404.html` for unknown paths, redirects `.html` and trailing-slash URLs to clean URLs, and attaches the custom domain `articles.armenderoian.dev`. `workers.dev` and preview URLs are disabled.

### From GitHub Actions (production branch)

`.github/workflows/deploy.yml` runs on every push to `main` (and manually via _Run workflow_). It installs, checks, lints, runs unit tests, builds, runs the integration tests, and then runs `wrangler deploy`.

One-time setup:

1. In Cloudflare, make sure the `armenderoian.dev` zone is on the account.
2. Create an API token with the **Edit Cloudflare Workers** template (Account › Workers Scripts: Edit, Zone › Workers Routes: Edit for the zone).
3. In GitHub: _Settings › Environments_, create `production` (optionally restricted to the `main` branch and/or with required reviewers), and add the secrets `CLOUDFLARE_API_TOKEN` and `CLOUDFLARE_ACCOUNT_ID`.

The workflow fails early with a clear message if the secrets are missing. No credentials are stored in the repository.

### From a workstation

```bash
npx wrangler login
npm run deploy
```

Use `npx wrangler deploy --dry-run` (after a build) to validate the configuration without credentials, and `npm run preview:worker` to test Cloudflare routing locally.

### CI

`.github/workflows/ci.yml` runs on pull requests and pushes to `main`: install, `check`, `lint`, `format:check`, unit tests, build, integration tests (including link validation), and the Playwright suite against the built site.

## Known limitations

- Mermaid diagrams render in the browser (only on pages that contain them) rather than at build time, to avoid requiring a headless browser in every build. Without JavaScript, readers see the diagram source.
- Search requires a production build; it is unavailable in `npm run dev`.
- Drafts can only be previewed locally with `npm run dev`; there is no hosted draft preview.
- The `theme-color` meta tag follows the system preference, not the manual theme toggle.
